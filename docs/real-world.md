# Проверка на реальных репозиториях

Чтобы узнать, сколько ложных срабатываний даёт линтер на настоящих инструкциях, он был запущен на 10 публичных репозиториях, где есть AGENTS.md, CLAUDE.md или `.github/copilot-instructions.md` (копия `git clone --depth 1` на 21 ноября 2026, без `--exec`).

Репозитории: astral-sh/ruff, biomejs/biome, langchain-ai/langchain, pydantic/pydantic, sveltejs/svelte, remix-run/react-router, withastro/astro, anthropics/anthropic-sdk-typescript, denoland/deno, microsoft/vscode. Всего 57 файлов-инструкций (из них 42 в одном VS Code). Каждый запуск на репозитории до 37 тысяч файлов занимает менее секунды на тёплом кэше.

## Что нашлось после калибровки

Всего **28 замечаний**; я просмотрел каждое вручную и сверил с репозиторием.

| Замечание | Сколько | Вердикт |
|---|---:|---|
| `too-long` (файл больше 6000 токенов; ruff, langchain, anthropic-sdk, ещё 2 файла VS Code) | 5 | верно по определению |
| `dead-link` в VS Code (`[index.ts](index.ts)` в `.github/instructions/`, ссылка на `hooks.md`) | 3 | верно: на GitHub эти ссылки сломаны |
| `no-commands` (pydantic, svelte) | 2 | верно: в файле действительно нет ни одной команды |
| `duplicate-line` (VS Code) | 1 | верно |
| `vague-instruction` («be careful», deno) | 1 | верно, замечание мягкое |
| `broken-path` | 15 | **7 спорных, 8 ложных** (см. ниже) |
| `missing-script` (`pnpm run typecheck` в VS Code) | 1 | ложное: в тексте «from the `build` folder», каталог запуска из прозы не вывести |

Итог: **12 верных, 7 спорных, 9 ложных.** Почти всё шумное сосредоточено в одном правиле, `broken-path`.

### Ложные `broken-path` (8)

- `../agent-host-protocol` (соседний репозиторий вне этого);
- `nls.messages.json`, `nls.keys.json`, `nls.metadata.json` (файлы, которые порождает сборка);
- `resources/app/ThirdPartyNotices.txt` (артефакт поставки);
- `workspace.yaml` ×2 (файл, который программа создаёт во время работы);
- `release-please-config.json` (условное упоминание «где автоматизация релизов пишет…» в anthropic-sdk).

Это класс «описание поведения программы, а не ссылка на файл репозитория». Что с этим сделано: строки со словами *writes, stores, produces, generates, outputs, create, example, for example* не проверяются; каталоги сборки, `.gitignore` и `.env*` пропускаются; голые имена исходников без каталога (`foo.py`, `_layout.tsx`, `stdarg.h`) не проверяются вовсе. Оставшееся подавляется комментарием `<!-- agentsmd-lint-disable-next-line broken-path -->` или `--ignore broken-path`.

### Спорные (7)

Ссылки на `pr-oss-check.yml` ×2, `protocol.md` ×2, `session.ts` (укороченный путь), каталог `versions/`, `aiCustomization.contribution.js`: похоже на устаревшие упоминания (файлы переименованы), но без истории репозитория уверенно сказать нельзя.

## Что изменилось по итогам проверки

Первый прогон на девяти репозиториях без VS Code дал 31 замечание, заметная часть ложных; после исправлений на тех же девяти осталось 5 (из них 4 верных). VS Code проверялся уже после основных исправлений (23 замечания). Исправлено:

1. **`CONVENTIONS.md`** убран из автоматического поиска (в ruff это был файл-пример с тестами).
2. **justfile**: алиасы (`alias f := format`) считаются командами (в biome `just f` помечался как отсутствующий).
3. **Голые имена файлов**: проверяются только конфигурация и документы (json, toml, yaml, lock, md…), а исходники без каталога нет.
4. **Строки про создаваемые файлы и примеры** не проверяются (см. слова выше).
5. **Менеджеры пакетов**: глобальные установки (`npm install -g`) и команды реестра (`publish`, `view`, `login`…) не считаются выбором менеджера проекта (в astro это была ложная пара `pm-inconsistent` и `pm-lockfile-mismatch`).
6. **`no-commands`**: любая команда считается (раньше требовалось слово `test` или `build`; в biome и anthropic-sdk команды были, но называются иначе).
7. **Вложенные файлы** (`packages/api/AGENTS.md`) могут использовать скрипты и Makefile корня: команды из них часто просят запускать из корня.
8. **Монорепозитории без корневого манифеста** (`make test`, а Makefile лежат в `libs/*`): каталог запуска из текста не вывести, поэтому `no-manifest` молчит.
9. **Ссылки, записанные от корня**, но считающиеся от каталога файла, вынесены в отдельное правило `link-root-relative` (предупреждение, с подсказкой написать `/путь`).
10. **Файлы-указатели** (AGENTS.md, который только отсылает к `.github/copilot-instructions.md`) не просятся добавить команды.
11. **`.js` по исходнику**: упоминание `foo.js` не считается ошибкой, если есть `foo.ts`; ведущие `./` и `../` отбрасываются при поиске пути в монорепозитории.
12. Порог `too-long` поднят с 4000 до 6000 токенов (оценка: байты / 4): при 4000 под него подпадало большинство настоящих файлов.

## Вывод

Правила про **ссылки, импорты, скрипты и менеджеры пакетов** сверяют текст с фактом и почти не ошибаются (одна ложная находка из 7 команд с проверкой скриптов, причина названа). Правило про **упомянутые пути** самое полезное для устаревших файлов и самое шумное для описаний поведения программы: поэтому у него низкая важность (предупреждение), несколько защит и способ подавления.
